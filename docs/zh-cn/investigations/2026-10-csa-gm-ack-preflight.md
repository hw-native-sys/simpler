# CSA 三 lane ACK 完整只读预检查：收益不足，撤回

日期：2026-10-28。

## 假设与边界

原 check_acks 对每条 lane 依次 query＋FAA0，遇到后面的旧序号才返回。
已有普通 ready 候选等情况下，外层仍进入服务，可能反复强读已到达前缀。
实验将 query 放到前面，见旧值等待；可能齐备后仍逐条 FAA0 和精确等号确认。
提前见未来值则转入原顺序的强确认，不让后面的旧值吞掉原有错误。
三 lane 资源条件、inactive lane、错误门禁、ABI 和业务不变。

基线 33685149…，候选 7db67da1…；TaskControl 均为 512B，schema 均为 v5。
候选通过 C++ 1121 项、Python 3335 项、两平台各 651 个边界场景和各九项 Mix N2 真实故障。
严格 L4 通过 2308 个执行身份、133 条依赖和 46733 个事件。

## 实测与决定

同卡 B/A/A/B，每批三轮七项 golden、5 次预热＋100 正式样本；源码和三个二进制成套切换，
54 个链接后 kernel 指纹相同。CLI 竞争监测为空；没有 task-submit 隔离，不等于系统级独占证明。

| 批次 | 完整 Device 中位数（us） | Host 中位数（us） |
| ---- | ------------------------ | ----------------- |
| B1 | 2409.3880 | 78510.2905 |
| A1 | 2432.1635 | 78297.4310 |
| A2 | 2421.1945 | 78267.2570 |
| B2 | 2417.8135 | 78200.0790 |

每臂 200 样本，合并 Device A=2427.2035us、B=2413.2675us，差约 0.57%；Host 基本持平。
第二对只差 3.381us，低于两批基线的 10.969us 变化。第一对差 22.7755us，未形成稳定差值。
不扩大本轮测量，撤回生产改动；不声称严格零收益，也不以正确性通过替代性能证据。
恢复 33685149… 的生产实现与匹配原生二进制，可靠成绩仍为此前验收的 2.413584ms。

新增 174 项边界回归在原实现和候选上均通过，保留用于冻结旧／当前／未来 ACK 顺序及迟到资源义务。
本轮没有验证最终全故障矩阵，也没有达到低于 2ms 的目标。

## 重开条件与证据

只有新负载或动态证据证明“带 ready 候选的重复部分 ACK 强读”构成显著瓶颈时再重开，
不把源码中可能省掉的 RMW 次数当作耗时收益。
