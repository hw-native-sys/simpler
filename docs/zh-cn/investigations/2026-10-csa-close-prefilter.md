# CSA 耗尽关闭预筛：未见收益，撤回

日期：2026-10-28。基线是合并准入观察及首个 READY 优先的版本，完整 Device 约 2.267ms。

候选在纯 C/V 无 READY、未 sync_claimed、未 ticket_exhausted 且本地形状／类型合法时，
用 cursor query 的正提示选择既有强 close，成功后继续下一义务；未关闭时回原 claim 路径。
没有把 query 当关闭证明，原 FAA0、错误门禁、活动槽和局部结束合同均保留。
目的是减少零工作成员的 claim 耗尽强读与紧接着的 close 强读重复。

新增 8 项功能回归在基线和候选上均通过；候选四个 C++ 目标、两平台各 91 个普通有序／sync_start
场景和原样 CSA 严格 L4 通过。保持 2308 个执行身份、133 条依赖和 46733 个协议事件。

每批均为三轮七项 golden、5 次预热和 100 个无泳道图正式样本，顺序如下：

| 批次 | Device 中位数（us） |
| ---- | ------------------- |
| 修改前基线 | 2259.8695 |
| 关闭预筛候选 | 2284.8390 |
| 恢复基线 | 2262.5875 |

候选比随后恢复的基线慢约 0.98%，没有观察到足以保留的收益，未扩大本轮重复测量。
这不证明所有负载都无收益。新增 query、形状门禁和分支有成本；成员关闭数量也不等于实际可省
FAA0 数量，已经持有无效尾票的成员原本就只需要一次强关闭。不能将历史170ns乘以成员数当作收益。

撤回生产分支，保留8项耗尽安全回归，恢复首块优先版源码及匹配原生二进制。

`idle-first-ready-after-b`、`idle-close-after-a`、`idle-close-before-a`，原始结果不覆盖。
候选二进制保留在同级 `runtime-idle-close/`；本地无 task-submit，正式计时无并行构建／测试。

仅在新的动态调用证据或负载证明该重复强读占据关键路径时重开此控制流方案。
