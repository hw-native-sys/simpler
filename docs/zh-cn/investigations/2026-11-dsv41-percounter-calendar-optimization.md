# DSV4.1 Percounter 日历调度优化复盘

本次工作从 #3239 的两个问题出发。候选日历需要把依赖观察、进入 kernel 和核退役的代价算进去，
排核也需要在原贪心策略附近尝试其他合法顺序。DSV4.1 整网实验进一步把问题定位到设备上的依赖等待。
最终提交同时改动 Host 的排程和打分、设备侧的等待，以及预计算等待关系的成本。
[问题与验收背景](https://github.com/hw-native-sys/simpler/issues/3239)

## 测量口径与基线

- 工作负载为 DSV4.1 Flash DSpark 的完整 target 和 drafter decode。EP2/DP2/TP2 与 EP8/DP8/TP8 都使用每卡 B12、上下文 8192、每卡 72 个 target rows、12 个 target expert 和 4 个 draft expert，路由均衡。
- 基线运行时为 `d96bb9317`。PyPTO-Lib `19c6ac0e`、PyPTO `22371da7`、PTO-ISA `45435c06`、PTOAS 0.78、CANN 9.3.0。每个拓扑的主线与候选复用冻结输入和 kernel。运行时堆分别固定在 EP2 的 4 GiB 和 EP8 的 8 GiB。
- 最初的 EP2 回放中，Host 下发偏斜中位数约 330 ms，最慢 rank 的 RunWall 随偏斜变化。最终测量在设备上对齐每轮起跑，并在每轮前恢复可变输入。AICore wall 从首个业务 kernel 开始计到末个 kernel 的输出栅栏。每轮取最慢 rank，再对所有计时轮取中位数。RunWall 单列。
- L0 用于验收，L2 用于解释等待。L2 分两次采集依赖图和时序，每次都恢复输入。筛选在 10 轮预热后计时 40 轮，最终复测在 10 轮预热后计时 100 轮。

验收从最初的相对加速量调整为同拓扑的 `1 µs ideal + 1 ms`。模型固定主线每核执行顺序、实测 kernel 时长、
本地依赖和跨卡依赖。MIX 的同一 block 和显式 `sync_start` cohort 分别作为共同启动组。
一个启动组在前驱和资源都可用后支付 1 µs。跨卡 EP 发布约束接收端逻辑完成，TP 发布约束 TWAIT 的结束。
这是在主线排核条件下的重放，适用于本次验收口径。

| 拓扑类型 | 主线 L2 日历行数/每 rank | 跨卡边数 | 零调度理想值 | 每组 1 µs 理想值 | 验收上限 |
| -------- | -----------------------: | -------: | -----------: | ---------------: | -------: |
| EP2/TP2 | 60,242 | 180 | 19.282865 ms | 20.284625 ms | 21.284625 ms |
| EP8/TP8 | 63,726 | 5,040 | 17.201332 ms | 18.188400 ms | 19.188400 ms |

两种拓扑均从每 rank 的冷 PGO 记录确认 87 个 `sync_start`，再映射到 L2 逻辑任务。EP2 的跨卡边为
172 条 EP 异步完成边和 8 条 TP TWAIT 边，EP8 分别为 4,816 条和 224 条。把 TP TWAIT 的本地占用理想化为零时，
EP8 的 1 µs 理想值为 18.164187 ms，最终实测中位数仍在其 1 ms 内。

## 先改候选日历，再定位依赖等待

这一阶段用同一对 A5 1、2 号卡，每个版本计时 100 轮。最初统一记录 RunWall，后续同时保留 AICore wall。
主线两次测量记为 A1 和 A2。最终 EP2 对照使用 A2。

| 实验版本 | 改动内容 | RunWall p50（ms） | 证据与取舍 |
| -------- | -------- | ----------------: | ---------- |
| A1 / A2 | 原主线在线 PGO | 24.260177 / 24.280730 | AICore p50 为 23.619769 / 23.649144 |
| B1 | 重放候选自身的等待和进入事件，试用长输出 block 优先 | 24.241717 | 较 A1 快约 18 µs。L2 输入等待接近主线，仅重排 block 收益很小 |
| B2 | 排程优先级计入等待开销及整组工作量，探索多个时间窗口 | 24.111434 | 较 A1 快约 149 µs。关键链上的 START 等待下降，五个候选使每 rank 冷训练约 944 ms |
| C1 | 单独去掉可由 64 项局部依赖窗口证明的传递等待 | 23.867339 | 较 A1 快约 393 µs。L2 的 fan-in 汇总槽约从 750 降至 481–485，输入前空档同步下降 |
| D1 | 结合等待费用与依赖证明，加入有界回填，收敛为三个候选 | 23.629141 | 较 A1 快约 631 µs。两 rank 都选择回填，冷训练约 339–341 ms |
| E1 | 用真实 DAG 链证明更远的传递依赖 | 23.320193 | AICore p50 为 22.747155 ms。汇总槽降至约 285，关键链输入前空档约 2.75–2.77 ms |
| F1 | 使用相对资源就绪时间的窗口，扩到八条 DAG 链，并复用同核已观察的依赖 | 23.214989 | AICore p50 为 22.631542 ms，距 21.284625 ms 上限还有 1.347 ms |

回填只检查最多四个同资源类别的候选块。只有能放进空档并保住所选任务预计启动时间的候选才会前移。
最终打分重放具体的 wait list、helper、MIX 和 START 事件，同时区分逻辑完成与物理核退役。
同一批主线 kernel 时长套用 E1 的实际排核时，1 µs 结果为 20.297718 ms，和主线排核的 20.284625 ms 接近。
E1 的实测进步主要体现在从完成发布到后继输入可用的时间。

为控制冷训练成本，排核改为增量更新受影响的有序核可用队列，单个占用变更只更新相交的核组合。
固定 helper 宽度下，事件打分按拓扑顺序遍历事件和边。28 组由 L2 重建的离线试验中，
布局及等待表指纹一致，构建中位数约从 150 ms 降到 97 ms。事件图改用紧凑邻接存储后，
单个候选打分约从 40–50 ms 降到 14–17 ms。控制行较少时用一张位图传播退役证明，
40 组离线布局的等待表和打分一致，单个计划的构建约从 90–99 ms 降到 52–54 ms。
这些离线试验的阶段耗时有重叠。最终冷训练应以整网采样为准。

## 整网复测与证据

| 拓扑类型 | 设备编号 | L0 p50 | L0 p90 | 高于 ideal | 上限内轮数 |
| -------- | -------- | -----: | -----: | ---------: | ---------: |
| EP2/TP2 | 1、2 | 21.163032 ms | 21.225043 ms | 0.878407 ms | 100/100 |
| EP8/TP8 | 0–7 | 18.972782 ms | 19.034174 ms | 0.784382 ms | 99/100 |

EP2 同卡主线 A2 的 L0 p50 为 23.649144 ms，整体下降 2.486112 ms。EP8 使用同一份最终实现，
40 轮筛选 p50 为 19.014108 ms。100 轮复测中最慢一轮为 19.190650 ms，高于其上限 2.25 µs。
两种拓扑均按最慢 rank 的中位数达标。冷 PGO 的 Host 计时在 EP2 从主线约 144 ms 增至候选 245–253 ms，
EP8 从主线约 153–164 ms 增至候选 261–295 ms。主线统计读回后的 Host 阶段，候选统计事件打分和计划筛选。
两者都在冷训练中支付，热跑复用缓存。

按 L2 实测事件回溯每个 rank 的观测关键链，EP2 输入就绪前的累计空档从 3.405–3.456 ms 降到 1.367–1.377 ms，
EP8 从 3.387–3.494 ms 降到 1.449–1.510 ms。EP2 同一批 `combine_reduce` 的末前驱 DONE 到首块 InputsReady
中位数两侧均从约 3.7–3.8 µs 降到约 0.6 µs。EP8 Rank 0 的 40 个 `ffn_scatter` 任务同口径从 6.350 µs 降到
1.280 µs。L2 轨迹也记录部分任务等待增加，关键链总空档的减少给出了整网推进变快的证据。

合成用例只提供输入，正确性以历史主线作差异校验。九份可见整数解码输出中，EP2 的 672 个元素和 EP8 的
2,688 个元素均逐项一致。EP2 与 EP8 的两组 L2 均核对了记录丢失和 defer 更新配对。

## 检视修正

- 回填任务和原选中组使用同一组核连续提交。放入空档的任务可以压线退役，原组保留预计启动时刻。跨资源类别的回归用例覆盖 MIX 重新进入窗口后抢占 Cube 的情况。
- 候选重放按首次观察到的 owner token 或周期性 DONE 查询放行 follower。可融合的 fan-in 直接检查生产者的总完成计数，模型仍计入 defer 路径所需的 helper 到达。
- 融合资格随日历保存，候选评分与设备绑定共用同一份判断。祖先遍历最多访问输入依赖边数的 16 倍，预算用尽后，未完成证明的组走普通 fan-in。
- 融合 helper 在只差两个 credit 或读到本生产者的 defer bit 时紧密重查，宽组远离阈值时继续按簇错峰。此处修改只影响已分配的融合 helper。

### 固定日历轮询对照

独立采样 PGO 时，EP2 完整修复的 p50 比仅 Host 修复高 13.413 µs。固定日历复测使用同一 Host 二进制、逐卡重放同一份 PGO 样本、核对日历指纹，只切换 AICore helper 的重试间隔。两组预热 10 轮、计时 40 轮，p50 从 17.857547 ms 降到 17.852332 ms，p90 从 17.902117 ms 降到 17.895836 ms。两组 672 个元素逐项一致。独立训练时的 13.413 µs 差异在该对照中未复现。

### C2A full 受控对照

同版 Lib 的 C2A full 在同一张卡上复用冻结输入，预热 10 轮、计时 100 轮。修复前和完整修复均通过 golden 校验，AICore wall p50 从 192.904 µs 降到 190.288 µs。

候选评分使用同一次冷 PGO 的 816 行样本。固定 `submission` 布局时，修前和修后的评分为 193,775 和 192,658 周期，两套评分都选中 `submission`。固定修后的评分器时，保留预留改变了 `backfill` 的排核指纹，两种 `backfill` 的评分均为 199,543 周期。#3239 所列 C1A 对照仍是后续验收项。
