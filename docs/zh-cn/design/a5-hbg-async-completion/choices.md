# A5 HBG 异步完成待验证选型

[返回总览](../a5-hbg-async-completion.md)。本文列出会影响实现的未决问题及替代方案，不重复定义基础协议。实现先遵守[基础设计](protocol.md)；候选只有满足相同语义和验收条件后才能替换对应部分。

## 普通 ready 队列的实现范围 {#ready-queue-implementation-scope}

当前只保留 **T/H8**：按 AIC/AIV/MIX 类型分池，ticket 数组发布，组宽固定为 8，所有合法消费者均可跨组领取。每四次搜索优先访问远端组的规则保持不变。

T/G、T/H4、L/G、C/W1/W4 未完成当前异步实现下的功能与性能验证，其配置入口、原语和专用服务路径已删除。graph-task 阶段的历史结果不能作为当前实现资格，也不能据此判定候选优劣。

以后重新比较全局队列与分级队列时，需要基于当前代码重新实现候选，并重新证明：有界发布及交权期间的唯一所有权、异步 FINISH 可跨核续接、业务与 CHECK/FINISH 的进展、MIX 实际资源参与、错误退出后的 backing 生命周期。候选先通过相同功能、故障与 2/4 rank 验收，再使用相同基线和计算产物比较性能；不能直接恢复旧代码作为可运行选型。

## 1. 选型规则与能力门槛

| 类别 | 处理方式 |
| ---- | -------- |
| 正确性与硬件能力 | 验证失败即阻止对应功能交付，不能用更快的错误行为替代 |
| 等价实现 | 比较相同功能、错误和资源合同下的完整成本，再选择一个生产实现 |
| 合同变更 | 收窄观察核、放宽错误隔离、改变公开兼容性等，须先更新目标和验收条件 |

每项实验必须先固定输入、工作量、基线、观察指标和通过条件。使用独立构建产物对照，不新增全局用户开关，也不将多个实验协议长期同时保留。最终选择同时更新接口/协议文档及其测试，不能只在代码中改变行为。

### 全核条件观察

待确定的是 AIC/AIV 对 COUNTER32 和 SDMA64 的具体观察指令及数据获取序列；`observe_once` 的返回合同和全核观察目标已经确定。

候选包括精确宽度的 device-direct load，以及具备对应核资格的 backend 读取路径。使用 UB 的实现只有在该核具备相应能力时才成立；对外部条件地址进行 atomic-add-zero 不属于等价候选。

必须同时通过目标编译与真实 A5：自核/异核观察、延迟条件、旧 cache、目标旧 dirty cache、不同提交/观察/消费核、严格地址范围和重复 generation。若某核组合无法满足合同，先补后端能力；固定由另一核代理不能被计作全核观察通过。

消费者获取路径单独验证：优先复用已有读取原语的获取保证；存在缺口时才比较精确范围的显式维护。两者都须满足[消费者可见性要求](consumer-preparation.md)，不能以消费者本身不登记条件跳过证明。复用资格按 silicon、backend 版本、核和实际读取路径记录；公共完成记录 API 只提供条件，不自动提供这项资格。

## 2. 表示与汇合

### 条件表示与分配

保留既有 32 B completion entry，不增加 per-condition binding index。基础实现按物理执行预留登记容量；比较实际异步密度、每执行 1/4/64 条条件、bind 初始化、H2D 字节、run 峰值空间及同步调度开销。

候选优化可以压缩内部索引、减少零登记执行的初始化成本，或在保持稳定记录和有界分配的前提下按实际使用分配。不得以新增强制的 Host capability/资源声明协议作为默认前提，也不能用可提前复用的 dispatch slot 保存未满足条件。

### 按实际登记维护 pending

基础协议采用 P/R/closed：P 只统计未完成非零 group，R 记录累计登记数；关闭计算依赖原有真实 block/lane 释放汇合。零登记不增加 CHECK 责任，全零 task 同步完成。其正确性要求与原子位布局由[协议](protocol.md)定义。

令 B 为逻辑 block 数、G 为计划执行数、K 为实际非零组数。原有计算汇合的 B 次贡献是共同成本；额外异步计数由静态方案的 B+G 次，变为非零任务的 2K+1 次。全零 ordered task 只增加一次 close；非 ordered 全零 task 只做一次权威 R 读取。该比较不包含 lease、目录、缓存和数据发布，不能用操作次数直接预测延迟。

性能比较须包含非零比例 0%、低比例、50% 和 100%，真实 skip、多 block MIX、Graph 多实例及重复 run。正确性覆盖晚到登记、计算关闭与最后条件交错、发布者暂停和失败退出；P 暂时归零后还可登记，只要计算尚未关闭，就不得完成 task。

run 活动标记只消除从未产生异步工作的额外扫描和获取；一旦活动开始就保守保持激活。若混排 workload 需要更细粒度获取，只能基于实际数据依赖及发布版本论证，不能根据“消费者未登记条件”跳过获取。

## 3. 工作发现与空间

### 位图与直接 lease 扫描

基础目录使用专用 bounded strong-CAS 位更新。候选直接轮转 lease 表，以发布 lease 作为唯一发现入口，不维护活动位图；每次只观察有限条记录并正常进行版本 CAS。

小 E 下直接扫描可能省掉目录更新，大 E 或大量 DORMANT/TERMINAL 时可能浪费更多观察。比较 E、实际在途数、空闲核数、单热点、同字集中结束、短业务 kernel 和稀疏尾部；分别统计有效条件观察、目录更新、lease 交权、满足到发现及到消费者执行的延迟。最后 CHECK 可能含两次目录更新，须连同 lease/join/屏障单独计价，以 L1 整图结果决定是否替换，不能只比较普通 slice 的 8 个工作单元。

算术加减位图在错误重复贡献时可能污染邻位，不满足基础错误隔离要求，不作为本轮等价替代。缩短 CAS 重试次数后丢掉未发布工作也不是合法优化。

### 软分片

记录分配到固定 shard，每核具有本地优先区和远端轮转游标。分片仅改变发现偏好，不限制领取资格，不固定永久观察核。CHECK/FINISH 与本地/远端两个维度都要获得服务机会，例如四种优先组合循环；不能因本地持续有工作而永久不帮助其他 shard。

成功领取后仍只执行一个有界 slice，PENDING 立即交权，不增加冷却时间或私有待重新发布队列。验证多记录局部性、单热点、核忙闲不均及远端长期 RUNNABLE 的进展。多记录收益不能外推为已消除单热点争用。

### CHECK 已结束页剪枝

若稀疏尾部扫描成为瓶颈，可将每 64 个计划 group 组织为一页，增加 `unsettled` 和上层“未来仍可能有工作”位图：

1. Host 把 unsettled 初始化为该页计划 group 数，所有有效页的上层位为一；尚未执行的 group 占据责任。
2. group 终态、叶位已清且不会再发布后，唯一减少 unsettled。零登记/skip 也只有在不会再发布时才结算。
3. 最后递减者清除上层位，页位在 run 内不重新置位。页维护必须在 group 的最后 join 贡献之前完成。
4. 扫描器跳过已结束页，但不提前回收记录；上层位和空叶都不能代替 run 退休证明。

该结构只跳过所有责任均已结束的页，不是瞬时“页非空”摘要。代价是每 group 多一次计数 RMW、每页额外状态和上层观察；未执行页仍需保留。比较大 E/小在途、连续页完成、零登记和长期未激活 Graph，只有扫描收益超过新增成本才采用。

### 初始化与发布范围

基础布局把连续 header 放在初始化前缀，把 token 和按实际发布初始化的控制状态放在后缀；保留完整 backing，只缩小每轮清零和 H2D 范围。header 与 token 分别发布，零登记不触及后缀。连续 header 还允许直接按索引计算地址，省去 group offset 表；执行入口只准备映射，记录校验在实际登记及封口边界执行。

进一步压缩必须以实际 `sizeof/offsetof` 和 cache line 归属验证，不得让不同 writer 的 cached 写入或原子控制字共享回写行。比较 Host bind、实际上传字节及 Device 执行准备成本，不能只观察分配总长。

运行中复用池不属于首轮优化。若后续需要引入，须独立证明池满不会阻塞负责满足条件的 publisher，并新增 generation、归还及失败保留协议。

## 4. FINISH 与服务参数

### 有预算的直接 FINISH

实际登记过的 task 经过 FINISH 目录；全零 task 保留同步路径。候选只允许在计算关闭使非零 task 满足 P=0、当前位于 admission 前安全服务点且本轮异步额度未使用时，直接以 OWNED 执行预分配 FINISH，消耗同一份 slice 预算。

全部完成则无需目录发布；预算不足则保存 cursor，转为 RUNNABLE 并完成首次目录置位，再允许进入业务。由 CHECK 归还最后 P 触发时仍只发布 FINISH，不能在一次 CHECK slice 中执行第二条记录。

候选增加一个受 lease 保护的 `directory_published` 状态：从未发布的记录不能清位，发布后只清一次。必须覆盖每个 resolver 阶段的预算耗尽、错误和跨核续接；不得把未完成 cursor 留在原核私有状态，也不得在 cohort 许可之后插入执行。

比较零登记、条件已满足、长 fanout 和业务持续 ready 的负载。只有额外分支/状态未破坏同步短路径，且完整延迟或吞吐确有收益，才将此转换加入基础状态机。

### 服务预算

基础业务额度为四次返回，单 slice 的工作上限由协议定义。实验可分别比较业务额度及工作预算，必须把目录、领取、条件、路由、进度发布和不可让出尾部全部计入，不能把总工作量增加伪装成“同预算更快”。

报告业务吞吐、满足到发现延迟、FINISH drain 尾延迟及热点原子压力。更低检查延迟若造成稳定业务退化，需要按整图收益取舍；不存在对所有 kernel 时长都保证时间公平的固定计数。

参数选择不引入 per-record 重试时间、sleep 或固定观察核；纯 PENDING/碰撞也不被当作真实进展。选择后更新协议常量和对应最坏工作量测试，不保留未经约束的自适应模式。
