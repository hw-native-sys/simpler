# A5 PGO 日历中由前驱核直接通知后继核的 DMB 设计

目标是在给定日历落核的情况下缩短 kernel 间隙。AIC 成员向 CntNotify 提交本成员的完成计数。AIV 成员按日历订阅关系，用 MTE3 向后继核的 `DATA_MAIN_BASE`（DMB）写入通知序号。纯 AIC 前驱的后继在入场时查原有完成计数，随后每隔 300 个 SYS_CNT 周期复查。MIX 同时计入 AIC 和 AIV 的完成贡献；AIC 最后完成且没有后续 DMB 通知时，后继也能凭计数达标放行。

本文讨论 A5 Percounter 的 PGO 日历。发送方执行 `INC(1) → dsb(DSB_DDR) → 写对端 DMB`。接收方只在本轮 CntNotify 达到阈值时放行。即使 DMB 写早于计数可见，或上一轮的写迟到，本轮仍可在后续复查中取得完成证明。[主线日历实现](../../../src/a5/runtime/percounter/README.md)

## 2. 四任务菱形怎样交接

用现有 `synthetic/mpmd_diamond`。A、D 是 AIC 任务，B、C 是独立的单 block AIV 任务。沿用参考 PDF 第 9 页的订阅、到达和按期望计数放行的语义。PGO 确定订阅者所在核。B、C 的实际完成次序由设备执行决定。本设计允许每次到达都提醒订阅者，最终放行由订阅者判定。[订阅通知图（PDF 第 9 页）](https://gitcode.com/tingwood/runtime-doc/blob/main/design/PersistentKernel/00%20Dev%20runtime%E5%8A%9F%E8%83%BD.pdf) · [菱形编排](../../../tests/fdwic/dsv41_scheduler/kernels/synthetic/mpmd_diamond.cpp)

| 依赖 | 前驱完成后 | 后继的执行条件 |
| ---- | ---------- | -------------- |
| A → {B, C} | A 向原有 DONE 计数贡献一次 | B、C 各自在入场和定时复查时检查 A 的阈值 |
| {B, C} → D | B、C 各自执行 `INC(1) → dsb(DSB_DDR) → 写 D 的 DMB` | D 在入场、收到本轮新通知或定时复查时读取 SRAM，计数达到本轮阈值即可执行 |

**单前驱扇出。** A 的输出屏障完成后提交 DONE。B、C 共用这一份完成证明，各自观察到 A 的本轮阈值即可启动。若 A 是单成员 AIV，它还可用 MTE3 提醒接收行提前查数。接收行使用原始 `CalendarWait` 中的地址和累计阈值；复用计数链时，阈值可以大于 1。

**发送端保序。** 需要发送 DMB 通知的 AIV 先发出本成员的 DONE 或独立汇合计数增量，再执行一次 `dsb(DSB_DDR)`，随后写对端 DMB。一次增量之后连续通知多个目标时共用这道屏障；中途再发出汇合增量时，在对应通知前再执行一道。DMB 发出后直接继续日历。MTE3 批尾只设置完成事件，借出的 UB 源区在再次使用或移交时才等待。业务 kernel 返回处已有的输出屏障单独约束业务输出与 DONE 的顺序。

**双前驱汇合。** HBG 真机的同步 SPMD 尾部已有这两步。每个执行成员在输出有序后调用 `scheduler_publish_counter_credit()`，向 SRAM 发一次无返回值的 `INC(1)`。等待方调用 `scheduler_observe_task_completion()`，按阈值判断 DONE。将这个分工用于菱形，每个生产者在发出计数后插入一道屏障，再写目标 DMB。D 进入等待时读取一次计数，随后在本轮新通知或距离上次实际查数满 300 个 SYS_CNT 周期时复查。汇合路径上的 GM 原子操作为零。[HBG 完成记账](../../../src/a5/runtime/host_build_graph/runtime/scheduler/scheduler_completion_counter.h) · [HBG 完成判定](../../../src/a5/runtime/host_build_graph/runtime/scheduler/scheduler_ready.h)

1. 启动前为本次汇合绑定 CntNotify 和阈值。独占且清零的计数器阈值为 2。沿用单调计数区间时阈值为 `base + 2`，须证明该区间内只有 B、C 各贡献一次。为 D 绑定本轮两个不同的 DMB 值 `g/B`、`g/C`。两者均区别于启动时登记的初值。
2. B 完成原有的输出屏障后，依次执行 `INC(1)`、`dsb(DSB_DDR)`、向 D 写 `g/B`，随后继续自己的日历。C 采用相同顺序写 `g/C`。两个生产者都无需读取计数，也无需知道另一方进度。
3. D 先用 `MOV` 采样本核 DMB，再读一次 CntNotify。计数未达标就继续采样。本轮有效的新序号立即触发查数。其余采样在距离上次查数满 300 个 SYS_CNT 周期时触发查数。两种条件同时成立只查一次，每次按原阈值放行。

**工作假设及其推论。** 对 B、C 分别假定，当 D 能看见该前驱的 DMB 写时，该前驱贡献的计数已经能被 D 读到。两核之间的完成顺序任意。由此可以检查三种时序。

- **第一条通知早到。** D 看见 `g/B` 后读到 1。可见的这一份贡献一定来自 B，所以 C 的通知尚待到达。若 C 先到，交换 B、C 即可。
- **第二条通知落在重新等待的窗口。** D 保存的是触发上次检查的 `g/B`。C 在 D 读到 1 后写入的 `g/C` 即使早于下一次 `MOV`，D 仍能发现变化并再次查数。
- **两个通知都先于 D 的首次观察。** DMB 只留下最后写入的值。此时两个前驱的计数都已可见，D 只查一次就能执行。D 在较早的通知上已经读到 2 时也立即执行。本轮该物理目标只绑定这一行。

周期复查使 D 在计数先达标、最后一个 DMB 写仍在途中时即可推进。无新通知时，查询间隔以接收核真实查数后的设备时钟为起点。达到阈值后沿用原有 kernel 入场屏障。[CntNotify 访问](../../../src/a5/runtime/host_build_graph/runtime/scheduler/scheduler_memory.h) · [PGO 输出与入场屏障](../../../src/a5/runtime/percounter/aicore/lane_loop.h)

**现有真机证据。** 发送端加 `dsb(DSB_DDR)` 的一次 AIC → AIC 试写中，D 读到 DMB 新值，随后第一次读计数为 2。此次取样只能确定计数在这次读数时已可见。它与上述工作假设相容，硬件是否保证跨端点顺序仍待确认。[顺序验证用例](../../../tests/fdwic/peer_dmb_ordering/README.zh-CN.md)

L2 在接收核把读取 DMB 的 `MOV` 和读取 `SYS_CNT` 的 `MOV` 相邻放置。泳道中的 `MOV DMB · changed token` 表示先前采到过不同值，`previous_poll_cycles` 给出上次采样时刻。`MOV DMB · first sample` 表示进入等待时的首次采样，此时通知可能已经到达。`Periodic CntNotify check reached threshold` 表示定时复查放行，附带计数和从上次查数到本次采样的周期数。随后进入 kernel 的时间独立记录。SPMD 广播用本轮序号配对发送者，单目标写按目标核和通知值配对。发送开始到接收采样包含批内发射位置及接收轮询的影响。被后续写覆盖且未采到的通知没有接收时间戳。

## 3. 一个核只有一个 DMB

菱形中 D 的两次通知属于同一汇合，可以互相覆盖。单成员协议为每个物理目标核在一次 launch 内绑定一个订阅行，给同一行的两个来源分配不同的通知值。规划器为地址冲突的其他单成员行保留原等待，同核顺序已满足的依赖可直接省掉。DMB 的值只决定何时查数。

- **启动与绑定。** Host 缓存逻辑 worker 和订阅关系。AICPU 从本次握手取得真实寄存器窗，在 CntNotify START 前对选中的目标读取 DMB 低字 `old`。单成员菱形的通知值以 `(old ^ 2) & 2` 为基值加来源序号 0 或 1，均与旧值不同。重放时重新绑定。 [核发现](../../../src/a5/runtime/host_build_graph/aicpu/aicore_lifecycle.cpp) · [PGO 启动准备](../../../src/a5/runtime/percounter/aicpu/supervisor.h)
- **成功与复用。** 发送核发出 DMB 写后继续推进，退核前完成本核 MTE3 源区的回收。下一轮启动时，AICPU 按目标寄存器的当前值绑定通知序号。上一轮的旧写即使恰好命中新序号，也只能触发对本轮阈值的复查。CntNotify 按现有租约管理，共享单调计数的各区间有序且有效计数不能回绕。[CntNotify 容量与生命周期](../../../src/a5/runtime/percounter/README.md#cntnotify-capacity)
- **取消与超时。** 等待核检查 EXIT 并在退核时应答。启用对端通知的核组等所有成员确认后才释放；超时会保留整组。下一轮仍须满足本轮的完成阈值。

## 4. 实现与入口

| 改动位置 | 实现方式 |
| -------- | -------- |
| Host 选边 | 在最终 PGO 落核和 `plan_calendar_waits()` 消冗之后，选择仍需实际等待的依赖。单成员直接通知要求同一普通 phase、同步完成声明、无谓词、无 `sync_start` 和单 block。按图和 worker 判定。SPMD 选边规则见第 4.1 节。当前 `plan_fused_fanin_credits()` 要求 consumer 本身有后继且至少有足够的轮询行。菱形 D 是终点、只有一行，主线不会自动给它分配融合计数。为这条新规则绑定共享阈值时，要核对 B、C 的全部完成观察者和 range 尾，已有独立观察的任务保留原有完成语义。 [放置与等待规划](../../../src/a5/runtime/percounter/host/calendar_plan.h) |

| 可适用范围 | A5 真机在单一普通顶层 phase 中检查实际等待行及其前驱的同步完成声明。MIX 和普通多 block 的适用条件见第 4.1 节。Graph、异步完成、带谓词和缺少完成声明的任务沿用已有日历协议，负责推进异步前驱的等待行继续处理登记记录。 [延迟完成服务](../../../src/a5/runtime/percounter/README.md#completion-and-defer) |

单成员直接通知为每个订阅 worker 绑定一个独占的等待行。菱形的 A 保留一次原有 DONE，因为它与终点 D 共享一条完成计数链。B、C 各自的一次 DONE 构成汇合的两份贡献。若两个前驱都只在 AIC 上执行，后继沿用原等待，保留其他消费者需要的 DONE，也无需为对端通知额外申请 CntNotify 或绑定 DMB。

生成或打包工具可通过 `CoreCallable.build(..., completes_on_return=True)` 声明该 kernel 返回时输出已完成。声明绑定到实际指令字节。旧包、未声明或指令已变的 kernel 都沿用原等待。已声明的生产者如果实际登记了待完成的异步条件，本次运行报错并走退出流程。模型测试的 A、B 两版共用相同的标注包、指令和输入。

### 4.1 SPMD 与 MIX 的跨核通知

Host 按实际日历行选择存在单个逻辑前驱的依赖。源和目标的活动 kernel 都须声明返回即完成，且至少一端有多个 block 或多个执行成员。有谓词、异步完成、已有融合计数或委托其他行处理输入的情况沿用既有等待；Graph 内部行沿用 Graph 的原有协议。

- **成员完成。** 每个前驱成员向原 CntNotify 贡献一次 DONE。AIC 提交完成计数后即可推进；需要独立汇合计数的 AIC 也提交该份贡献。AIV 只有一个目标 worker 时执行 `INC → DSB_DDR → 写目标 DMB`。多个目标时，发送者在 INC 之前准备并校验读地址和阈值，随后连续执行 `ST_DEV(1) → DSB_DDR → LD_DEV`。每个 AIV 发送成员读一次累计值，观察到整项完成即可广播。多个成员观察到同一阈值时都能通知。
- **批量发送准备。** Host 按后继的实际等待行生成有序 worker 列表。使用同一列表的前驱共享一份日历发送表。每轮 START 前，AICPU 根据本轮握手得到的物理核映射和 DMB 初值，将地址连续写入发送表，并判断是否可以共用一个 token 基值。核映射和基值在每次启动时重新绑定。
- **AIV 批量写。** 共同基值只需一个 4 B 的 UB 源字。启动时，AICPU 核对实际订阅地址，尝试将等步长的地址或两列交错地址编码为 MTE3 命令，一条命令向多个目标各写 4 B。递减地址段从最低地址开始发出，通知仍由各个后继独立检查；任务依赖顺序由完成计数保证。命令放在共同基值路径闲置的逐目标基值数组中。编码能放下时，AIV 直接从日历发出这些命令。否则用 MTE2 将地址表搬入 UB，再逐目标发出。基值各异时，每个目标使用独立的 32 B 对齐源字。批尾只发布完成事件；UB 再次借用或该核退出日历时才等待。单目标由 AIV 发出一条 4 B 的 MTE3 写，等待延至复用 UB 时。L2 记录批量首尾下发区间，并给出实际目标数和 MTE3 命令数。
- **序号与复用。** Host 为每个被选前驱分配互不重叠的序号段。成员按 block 和角色取得序号，与目标 DMB 启动初值做异或。每个成员对同一目标最多写一次，同一物理核可以依次处理多个 SPMD 等待行。为单成员等待行分配的 DMB 在本次启动内独占，完成证明取自该行绑定的计数阈值。所有寄存器地址都在本轮启动时绑定。
- **输入证明。** 等待者先采样本核 DMB，随后检查原 CntNotify 的累计阈值。首次检查即可放行已经完成的前驱；尚未完成时由 DMB 变化或 300 周期定时条件触发复查。从不同前驱迟到的通知也只会触发一次复查。L2 区分入场查数、序号变化查数和定时查数达标。未达标的定时复查只更新本地计时起点。
- **独立入核。** 主线 #3261 由 Host 为 `sync_start` 的各 block 预留不同的兼容核。每条原本需要等待整项 DONE 的日历行保留自己的检查。纯 C/V 由对应行自己检查，MIX 由本簇原领队检查，领队随后用 SSBUF 放行同簇成员。满足本行的依赖即可执行。不同簇的领队分别取得完成证明。[主线变更](https://github.com/hw-native-sys/simpler/pull/3261)
- **固定选边规则。** A5 真机在日历构建时自动检查普通多 block、带 `sync_start` 核预留和 MIX 后继的实际等待行。只有已具备整项完成计数证明、且满足上述同步声明和邮箱约束的行才能使用此协议。

## 5. 实施顺序与验收

1. **确认硬件通路。** AIC → AIC 的一次跨 die 试写已通过。菱形扇出和汇合也已完成下述验证。分别安排接收方先等待和发送方先通知，接收方同时校验序号与生产者写入的数据。再验证实际汇合需要的 AIV → AIC 跨簇路径及同一目标接收两个源的完整写。按上述顺序假设验证协议，采集新通知后的首次计数作为硬件观测。跨 die 能力单独记录。对未获支持的方向保持 CntNotify。
2. **单独测扇出。** 在相同落核的菱形用例中核对 A 的 DONE 贡献和 B、C 各自的阈值放行。用 L2 检查 AIC 的 DMB 写次数为零，并分别记录 B 和 C 的 kernel 启动时间。
3. **单独测汇合。** 固定扇出、落核和输入。用同一个 CntNotify 阈值，对比主线 D 的等待方式与启用 DMB 后的计数检查。运行 `balanced`、`b_last`、`c_last`，验证四个输出和 padding、每轮两次 `INC → dsb(DSB_DDR) → 写 DMB`。分别核对 D 入场时的首次查数、有效新序号触发的立即查数，以及距上次查数满 300 个 SYS_CNT 周期后触发的复查。两个触发条件同时满足时只读一次。L2 单独标记定时达标，按阈值确认 D 在两个前驱完成后恰好执行一次。覆盖两个通知在 D 首读前都已到达、第二个通知落在 D 读到 1 后重新等待的窗口，以及退出后再启动的情形。 [用例及解析参考值](../../../tests/fdwic/dsv41_scheduler/production/mpmd_diamond.py)
4. **用 L0 决定收益，用 L2 归因。** A、B 两版都包含相同的 CntNotify 启停迁移，使用相同的 kernel、输入和落核，记录实际日历与被选边。用 `task-submit --device auto --device-num 1` 申领设备并记录 `TASK_DEVICE`。同一用例在同一卡上按 A×5、B×5、B×5、A×5 连续执行，排除预热。记录四段均值、两版各十轮均值和差值，按主线单卡用例逐项报告 L0 AICore wall。L2 单独量 `end(A) → start(B)`、`end(A) → start(C)` 和 `max(end(B), end(C)) → start(D)`。再用生产者输出屏障完成、通知发出、接收方命中、进入 kernel 四个打点拆分交接。分支等待与 kernel 执行可以重叠，三条间隔不能相加。

## 6. 历史实验记录

以下 L0 读数来自按核类型分开发出执行器之前的镜像，当时 AIV 在 L0 可落到 AIC 编译的调度循环。这些计时保留作历史记录。评估 AIV 的 MTE3 通知收益需使用已修复入口的镜像；L2 当时具有独立的 AIV 执行器。[L0/L1 入口修复](https://github.com/hw-native-sys/simpler/pull/3306)

早期配对结果中，**仅迁移启停**就让均衡菱形从 7.96 降到 4.63 µs，六段满波 MIX 链从 37.61 增到 40.36 µs。新增 DMB 通知的收益须在迁移后的基线上重测。双前驱需实测的是 D 减少的 SRAM 查询与两次对端写及其排序开销。 [已有配对测量](https://github.com/hw-native-sys/simpler/pull/3263) · [七组用例与模型口径](../../../tests/fdwic/dsv41_scheduler/RESULTS.md)

**2026-11-25 初版验证结果（含退出回读）。** 七组使用最新启停实现作共同基线，每项两版各十个 AICore L0 wall 样本。七项全部通过数值校验。只有四任务菱形命中两条单前驱通知和一个双前驱汇合。均衡菱形从 4.5425 µs 增至 5.1212 µs（+12.74%）。另在同一候选二进制中固定扇出，将 D 从直接查询共同计数切换为接收 DMB 后查数，耗时从 4.7703 增至 5.0554 µs（+5.98%）。每项开销按各自的配对结果解释。

三轮均衡 L2 中每轮均观察到四次 DMB 发布，D 查询一次得到 2。B 晚和 C 晚的两种输入各三轮，D 每轮依次读到 1、2，执行一次。强制调度超时的故障试验里，A 和短分支 C 已写结果，D 的输出仍是初始哨兵。出现设备错误后原上下文拒绝继续提交。同卡新进程随后运行了 28 轮完整 DMB 菱形，数值均正确。

**移除发送核退出回读和目标位图。** 均衡菱形在同一张卡上按 A×5、B×5、B×5、A×5 对照，排除每段两次预热。A、B 都启用完整 DMB 通知。四段 AICore L0 wall 均值分别为 4.9736、4.6564、4.9036、4.8490 µs，两版十轮均值为 4.9113 和 4.7800 µs（−2.67%）。B 晚完成的三轮 L2 各记录四次发送，D 每轮依次观察到计数 1、2，执行一次。所有输出均通过数值校验。

**#3261 之前的 SPMD 六段链。** 使用原始 `full_wave_mix_chain` 的 32 个簇和 64 个 AIV。默认选边在 5 条依赖上各选择一个 DMB 等待者，一轮共 290 次写，三轮 L2 校验每轮 386 个成员的执行顺序和数值。设备 6 的同卡 ABBA 四段 AICore L0 wall 均值为 38.2026、35.7888、34.3976、38.5740 µs。与支持单成员 DMB 的去回读版本比较，十轮均值从 38.3883 降至 35.0932 µs。

**合入 #3261 后的六段链。** Host 保留各 block 原有的输入等待，MIX 继续通过簇内 SSBUF 协作。三个 L2 采样中，五条依赖各有 32、64、32、1、32 个实际 DMB 目标。t4 的两个成员均观察到完成阈值，各写 t5 的 32 个簇领队，共 64 次写。每轮均执行 386 个 kernel 成员。设备 4 上独立运行的十轮 AICore L0 wall 均值为 31.4506 µs。

**六段链 AIV 批量写对照。** 在设备 0 上，两次自动分配分别执行 Scalar×5、MTE3×5、MTE3×5、Scalar×5，每段另有两轮预热。第一组 AICore L0 wall 十轮均值从 31.9609 降到 31.8677 µs，第二组从 33.4220 降到 32.2236 µs。配对采集的三轮 L2 中，t1 的 AIV 发送者向 64 个目标下发通知，从首次写开始到最后一次写发出的中位数从 10.961 降到 10.471 µs。这个区间含逐目标 L2 打点。两版每轮都执行 386 个成员，五条依赖的后继均在前驱完成后启动。
