## L3 诊断与发布问题

包含身份适配的 `queue-block-work-dfx-v1` 完成 A5 构建，设备 6 的 1 项放置检查与 7 项场景检查通过。
同一 callable 的单轮 L3 捕获包含 19,208 条执行记录，身份完整。
任务为 `task_20261103_185142_364542524030`；比较对象是设备 1 的历史 L3 捕获，属于诊断对照。

| 指标 | 重构前 L3 | 独立 block L3 |
| ---- | --------- | ------------- |
| 关键路径跨度 | 39.221 ms | 52.428 ms |
| 任务间调度间隙 | 27.109 ms | 37.347 ms |
| out_proj（func 13）每层任务组跨度中位数 | 31.872 µs | 316.668 µs |
| out_proj 单 kernel 时长中位数 | 11.957 µs | 11.516 µs |
| 进入 out_proj 的关键路径间隙累计 | 4.242 ms | 16.888 ms |
| MLP 中先于最后一个 SPMD block 结束而启动的普通任务数中位数 | 59.5 | 94 |
| MLP 普通任务与 SPMD 的组合跨度中位数 | 284.554 µs | 484.912 µs |

func 13 每层有 26 个普通任务；func 14 才是同阶段的 24-block SPMD。
当前 func 13 的领取耗时中位数为 4.010 µs，领取结束到 kernel 开始为 5.809 µs，
启动被拉散主要发生在领取之前。旧 obligation 限制的解除改善了 MLP 重叠，但新的下发开销抵消了收益。

源码中确认了发布粒度问题：`scheduler_service_work_publications` 每完成一个逻辑任务就返回，
即使只用了 8 个 work 预算中的 1 个。因此一个普通任务 fanout 要穿过多次调度循环才能全部可见，
其间穿插领取、执行或空队列扫描。工作区修正为总预算 8，可跨逻辑任务、部分 SPMD 和 inline 服务使用；
准备好的保留批次若装不下剩余预算，下一轮先给它完整预算，避免饥饿。
20 项生产函数测试连续 2,000 轮通过，另有六后端 30 项工作队列测试及 AIC/AIV 编译探针通过；
该修正的真机收益见下文稳态结果。

拆出 lease/cohort 推进函数的试验未通过 MIX 真机检查，已撤回，详见
[内联拆分撤回记录](rejected-optimizations.md#work-protocol-outline)。
`queue-work-publish8-v3` 基于通过真机的 DFX 版本，只修改发布预算，已通过定向真机和 Qwen 验证。
完整诊断与捕获哈希见
L3 证据（本地 `qwen-block-work-diagnosis.json`）。

内置关键路径工具的执行跨度按逻辑 task 合并，包含同一 SPMD 的 block 间空档；
不能全部视为有效计算时间。诊断采样也不替代无 profiling 的稳态性能验收。
模型性能接近目标前，不恢复完整 19 项无 Graph 性能集。
