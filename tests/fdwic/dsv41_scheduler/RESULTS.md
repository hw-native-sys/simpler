## 测量版本与口径

- 测试日期：2026-11-14。`main HBG` 是固定展示列名，本次对应提交 `8e6aba9d48470fa0f0ab54027ebd18114262129a`；`main percounter` 对应测试时已更新并核对远端的 `hw-native-sys/main@21d2e9a103d5b7372dda4823fb37eab470544d0c`。测量使用固定提交的构建，后续 main 更新不改变这些数值。
- 纯 L0：1 次预热、10 次正式测量，每轮数值校验；指标为 `chip.run.runner_run.device_wall`，包含 AICPU、AICore 及 case 内通信，排除 Host 准备、前缀和预热。双卡每轮取两个 rank 的较大值，再求平均。
- 每个 workload 的三种用例配置和各 runtime 在相同设备上测量，轮换 runtime 执行顺序。全部通过 `task-submit --device auto --device-num N` 分配，并使用返回的 `TASK_DEVICE`。SWA、c1a_full、Engram 实际设备为 3；c2a_full、c1a_reindex 为 4；c2a_reuse、c1a_reuse 为 5；MoE、layers_19_21 为 6、7。
- A5 Ascend950DT_9581（32 AIC / 64 AIV）、CANN 9.3.0、默认 `-O3 -g`。相同业务 kernel、张量参数、输入、依赖和图结构；固定零权重，每 rank 72 个有效 token、补齐至 80 行、64 个本地 expert。结论仅覆盖本组输入。
- DSL 半同步为 143/280 个 SPMD 同步；全同步为 275/280，采用 `1 < block_num ≤ 64`，包含 64。超过 64 的 5 个任务保持不变；实际同步 AIC/MIX 均不超过 32 blocks。PyPTO-lib 保留原同步标记。
- 本次 percounter 的 6 组多卡用例也通过了实际数值验证；通信场景不计算下界和百分比差距。

## 下界与差距

- 同步约束下界按每个用例及同步策略分别采集 21 组 `21d2e9a103d5` HBG L1（1 次预热、10 次正式采样），半同步与全同步不共用耗时或结果。L0 实测列不含这些 L1 采样。
- 模型保留任务完成依赖、32 AIC / 64 AIV 容量、不可抢占执行、MIX 同 block 共同启动，以及 sync_start 全部 block 的共同启动；调度成本为零，放宽具体 cluster 放置。持续时间向下量化到 100 ns，以 10 轮已证明下界的平均值入表。
- 这是固定实测 kernel 耗时条件下的模型下界，不是硬件绝对极限；L1 插桩、缓存和并发会影响输入时长，不能保证它是另一次 L0 的严格下界。不同同步配置的差值也包含各自 L1 输入时长的变化。
- **最优实测距下界** = `(min(main HBG, main percounter) / 同步约束下界 - 1) × 100%`。按未舍入数据计算，保留两位小数，不截断负值。
- **†**：该配置有轮次尚未证明模型最优，填写的是已证明下界，其百分比也是相对于该下界。16/21 组全部轮次最优，210 轮中 173 轮证明最优、37 轮仍有差距；不把可行排程时长当作精确极限。
