## 目标、口径与不可变约束

- 主目标：原样 HBG CSA 在 A5 上的完整设备侧 device_us 中位数低于 1500us，
  使用现有 RunWall 口径，包含设备启动、调度、执行和退出；不是仅让“额外调度开销”低于 1.5ms。
- 最终连续取得五个独立批次，每批 5 轮预热＋100 轮正式样本；五批中位数及合并中位数均低于 1.5ms。
  同时报告 P90/P99、最小／最大值和 Host 时间，不能只取最快轮次，也不以 Host 时间替代 Device。
- 固定 B=4、S=2、seed、输入／INOUT 初值、54 个 kernel、79 个有 kernel 的逻辑任务、
  原 block 数、2308 个执行身份、参数 ABI 和七项 golden；不重新生成或改写业务 kernel。
- 保留三 lane 资源组、GM 通道、固定 C/V 对应关系和有限 AIC 协调职责；不引入 SSBUF，
  不缩小 inactive lane 的资源义务，不在 Scalar 上建图或分配动态 heap。
- 保留完成驱动依赖、普通多 block 分波、sync_start 的每位置至多一次领取及最终一致性，
  保留 N=1 公共归一化。成员可在本地义务结束后继续，不增加全任务完成屏障。
- 完整输出可见性、不可撤销所有权、epoch／generation／group_seq、关闭 seal、故障入口门禁都必须成立。
  不用提前返回、漏记退出、移出实际设备工作、legacy 回退或放宽校验达到数字。
- Host 可以复用 HBG 已有的静态准备能力，但须报告 Host 和准备开销，
  不得把每轮实际设备工作藏到未计时阶段。未实现的三项功能 TODO 不混入性能主线。

## 起点与必须同时处理的两类开销

当前可靠起点是[实现过程记录](implementation-progress.md)与
[性能对照数据](perf_data/2026-10-27-csa-poursoul/comparison.json)中归档的候选：
Device 两批合并中位数 11.492358ms，L1 任务窗口 11.054759ms，
生产 diff SHA256 为 36b23ec1f79ce7a2bd8157664ff23a26b94af9ab0d6ba18bb4d5ab8e31d530ad。
对方约 7.2ms 只是中间参照，不是终点；
[同业务历史 AICPU 记录](csa-performance-20261026.md)的 Device 中位数为 2.133493ms，
也没有达到本次目标。它说明应进一步对照块级周转，但不能据此承诺 AICore 必然低于 1.5ms。

必须同时推进两条线：

1. 跨任务：准入、本核前沿、组关闭／后继启动，重点是 16 路投影／pack 的 2.764711ms 区间。
2. 任务内部：512 block 的 task 23 当前 L1 跨度已达 2.642464ms，单这个任务就超过最终预算。
   历史同 kernel 的 AICPU L4 对应跨度为 0.856807ms，采集等级不同，只作为可行性线索。
   不能只消除任务间空档；也不能把当前 task 首末跨度当成不可压缩的纯计算下界。

7.2ms、4ms、2ms 可作为进度检查点，但均不代表结项；在小改收益耗尽时必须进入块级周转优化，
不能无限停留在辅助检查和低收益微调。

## 对方分支的参考方式

复用已经获取的本地 refs/remotes/poursoul/a5-hbg-resident-spmd，固定提交
1d96d66c035582cfaae51cf98dbdd801c4a17379；不为同一轮比较重复拉取或悄悄移动参照版本。
重点核对该版本的 scheduler_spmd.h、scheduler_memory.h 和 Mix 路径，
不是把约 7.2ms 的插桩任务窗口等同于稳定的完整 Device 成绩。

- 借鉴“不变形状仅在头节点变化时重新观察”：对方 scheduler_observe_spmd_head 缓存 ref、mask、flags、N。
  当前方案可以复用已冻结的 task／run 元数据，但不能缓存跨入口的执行许可或最新前沿。
- 借鉴“先确认有地方放，再不可撤销领取，单次只领一个 block”：对方先检查 own/Mix 槽，
  再 CAS 领取，避免先取号后发现无槽。当前大 N 单块取号仍遵守这一资源边界，不扩大预留额度。
- 借鉴“耗尽不等于最后一次派发已经发布”：对方由成功派发最后一块的领取者推进 SPMD 队头，
  不是任何看到 cursor=N 的核都能推进。当前实现有独立组关闭、seal 和本核义务，
  应保留等价保证，不能直接照搬队头操作替代这些条件。
- 借鉴它对 query 与原子强确认的区分：CAS 可纠正陈旧的低 cursor，
  但最新前沿、错误状态或 payload 发布不能仅凭“query 快”替换 reader。
  本轮准入实验必须一起改变隔离信号的 writer／reader，并实测首次可见性；这不是直接复制对方实现。
- 不引入其 SSBUF／不同 Mix 槽组织，也不把单一 SPMD 队头假设套到本方案的全局准入日志。
  所有吸收项均受三 lane、GM 通道、固定 C/V 映射及完整故障门禁约束，并单独做性能对照。

## P1：缩短关闭、退役和后继推进之间的空转

主改造点：scheduler_dispatch.h、scheduler_admission.h、scheduler_gm_mix.h 及 executor 主循环。

- 对成功 retire 后返回主循环、成功 close 后下一轮才 refresh 的路径，尝试有界连续推进：
  retire → 在合法条件下领取／发布下一组；close → 观察后继 → 准备可执行工作。
- 只串接已经满足条件的步骤，不在 helper 内等待伙伴；到等待点、错误或工作量上限立即返回。
- 为零工作成员建立更短的检查／关闭路径，但仍须证明无未发布的本地领取、正确消费 seal，
  不能把 cursor 耗尽直接当作 task 完成，也不能忽略三 lane 控制义务。
- 保留 ready 发现与 completion 服务的公平性，避免连续推进独占 Scalar，使另一通道长期得不到服务。

先补／调整可控交错测试：迟到 release、最后领取者尚未 publish、seal 与下一 descriptor 交错、
本地先结束而远端仍在运行、mask 6 协调者、普通候选停放，以及控制链中途出现错误。
区分“必须隔一轮”这类实现策略断言与真正协议不变量；不删除所有权、可见性和执行许可断言。
收益首先看 16 路分支区间和本核前沿等待，再用完整 CSA 无插桩样本确认。

## P2：降低每个实际 block 的准备和重复校验成本

- 审查并复用同一 task／同一 run 内不变的元数据、参数布局与可安全复用的 payload 模板；
  block_idx、原 N、slot generation、epoch、真实地址及本次执行身份仍按实际调用更新。
- 将可证明属于同一有界控制步骤的重复校验收敛到明确的检查点；
  不跨轮、跨等待或跨 kernel 缓存“健康状态”和 entry permit。
- 优先消除重复工作，而非删除强确认。任何强读合并都要逐项说明仍保留的错误／所有权线性化点，
  并以已发布错误、迟到发布和旧代次反例验证，不能仅凭 CPU query 测试通过就认为 A5 可见性成立。
- 利用现有槽位预准备已证明可提前准备的部分，但“准备完成”仍不代表有执行许可，
  不覆盖活动组 mailbox，也不隐式增加在飞资源组。

重点检查同 callable 多轮复用、地址变化、INOUT 恢复、大／小 N 交替、坏 metadata、
缓存建立后的记录篡改和普通 predicate 只求值一次。单项收益不足时撤回，不累加理论收益。

## P3：重做普通多 block 的块级周转成本

这是冲击 1.5ms 的必要主线，不能以 P1/P2 有收益就跳过。

- 分析 task 23 的 512 block 为什么在当前 runtime 展开为约 2.64ms：
  分别检查领取争用、组间空档、参数重建、C/V 启动偏斜、完成计数与负载不均。
- 逐项评估保持现有额度的批量领取、领取控制的分片、同任务模板复用和现有槽位预准备，
  不直接改成模型／task ID 特判，不建立第二份依赖图。
- 优先保持已有未退役额度；若方案需要扩大预留范围，必须独立描述尚未发布工作如何阻止
  LocalDone、如何处理失败和回收，不能把“预留”改个名字就绕过所有权合同。
- 普通多 block 与 sync_start 明确分路：sync_start 不沿用多块预领，
  每个位置对同一 task 至多领取一次，早返回也不能再领。
- 领取耗尽、逻辑完成和资源释放三个条件继续分离。批量机制不能丢块、重领，
  也不能让某核持有不可完成的批次而造成后续同步任务死锁。

先在复用现有探针的 N=1／容量边界／超容量／512 以及纯 C、纯 V、Mix 上验证，
再回到原样 CSA。通过条件同时包含块级时间下降、分配不失衡、尾部不过度恶化及完整协议通过。

## P4：有证据地处理热点原子、布局与完成传播

- 根据动态计数和单项差分，定位真正共享的热点；不能把所有剩余时间归因于 atomic。
- 核对独立 cursor、完成计数和其他热字段的布局，按已有 128B 隔离实测依据评估拆分；
  同一个热点字的竞争不能靠 padding 消除，需考虑减少访问或分片。
- 需要 DIE 局部化时先查证实际核心／地址归属，不把逻辑编号的一半直接当作一个 DIE。
- 复用现有完成驱动 wake-list、ready inbox 与 direct 候选，缩短完成到后继可见／领取的路径。
  不新增另一套 ready 机制来掩盖旧路径，不改变“所有生产块完成且输出可见后才能释放依赖”。
- 更深的 ACK 确认合并或共享布局变化，要先给出三 lane 语义、发布顺序、错误门禁和
  旧／新序号的完整证明及测试，再实施；不自动变更已确认的组协议规则。

涉及布局时同步 Host、AICPU、AICore、采集器与解析器的镜像和静态断言；
完整重建并用二进制摘要确认实际测试版本，避免拿旧产物测新源码。

下一候选的具体边界（尚未实现，需先验证）：

- 评估在 TaskControl 现有 bypass 区的 padding 中放置 `claim_seal`，值为 N；不增加当前 512B 步长。
  只由令有效 next_block 恰好到 N 的那次合法 FAA／CAS 成功者发布，不能由看到 raw≥N 的任意核发布。
- 只有信号等于当前 N、且计数 query 与之相符时，才考虑复用该写入者已经取得的强确认。
  信号缺失或计数不符时保留原强读；坏值拒绝，不能让一条未经验证的 query 独立授予关闭或执行许可。
- 原 next_block／completed_blocks 和唯一执行身份保留。发布者尚未写信号不能造成新的永久等待；
  sync_start 已领取位置在 cursor<N 时的提前 LocalDone 仍按原强读处理，不增加全体完成屏障。
- 覆盖最后有效票已预留未确认、确认后尚未发布信号、N1 Mix、普通 N2/3/容量边界、
  早到／坏信号、计数不符、错误已发布、跨 run 重置与不参与当前任务的 worker。
- 若采用新字段，Host 初始化及准入准备须验证零值，原生证据显式升级并保留历史读取语义；
  新终态要求 seal 与实际有效领取数一致，不把 seal 当作 kernel 完成。复用已有首次可见性探针，
  检查阶段信号和新字共用 bypass line 时不混入 RMW／cached writeback。

## P5：设备生命周期与最终压线

- 在同一捕获中定位 bootstrap、register release、末尾 drain／exit 等固定开销；
  分别验证减少重复初始化、只触达实际使用区和安全复用已有准备结果的收益。
- 不减少运行 epoch 隔离，不提前宣布完成，不把未完成设备工作留在返回之后。
- Host 静态预处理的收益与代价分开报告；保持正式计时窗口，不靠均摊多次调用启动来替换单次 CSA。

## 每个候选的实施闭环

1. 写明一个可证伪假设、改动范围、不可破坏的不变量及预期改善的具体区间。
2. 先补能暴露相关错误的边界用例，再做单项改动；性能实验不伪称编译失败就是业务 RED。
3. 重建受影响 runtime，运行对应 C++／Python／仿真检查与必要 A5 故障路径。
4. 原样 CSA 的七项 golden 和严格 L4 来源／身份／因果门禁通过后，再测无完整插桩性能。
5. 同卡串行对照，正式采样期间没有编译、其他设备测试或设备查询；保留全部样本、
   失败批次和干扰记录。关键候选做前后复测或 A/B/B/A，落在噪声内则扩大验证或撤回。
6. 保留有证据的改进并扩大回归范围；无收益或破坏契约的候选撤回，不长期叠加实验分支。
