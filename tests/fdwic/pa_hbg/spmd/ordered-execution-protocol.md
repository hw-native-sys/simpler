# A5 HBG SPMD 运行时有序准入

[返回设计总览](../a5-hbg-spmd-design.md)。
复用完成驱动的依赖推进，在 ready 与 kernel 执行之间增加共同准入。
**task_ref 标识逻辑任务，order_key 标识运行时确定的顺序；两者不能混用。**
block 的领取、Mix 配对和完成发布见 [block 与 Mix 执行](block-and-mix-execution.md)。

## 完成驱动的依赖推进

### 保留现有 ready 和 wake-list

前驱完成后，沿既有 wake-list 推进等待任务的 fanin；依赖满足的任务进入按类型分布的
ready inbox，或成为 direct refill 候选。这仍是数据就绪的唯一主路径。
不为 SPMD 另建 TensorMap，也不让所有核反复遍历整份 fanin。

ready 节点仍代表逻辑 task，不为每个 block 重复把同一 task_ref 塞回现有 FIFO。
一次准入后用独立 block 状态分发工作，保留现有队列节点生命周期的边界。

逻辑状态至少区分以下含义，新名称仅表示协议：

~~~text
BLOCKED → DATA_READY → ADMISSION_CLAIMED → ADMITTED
                                             ↓
                            block 分配及执行可持续一段时间
                                             ↓
                                          TASK_DONE
~~~

需要执行 kernel 的 task 只在全部 block 完成后发布 TASK_DONE，并调用一次依赖释放路径。
DATA_READY、被某个核 pop 到、所有 block 已分配，都不等于 TASK_DONE。

### 就绪顺序与执行顺序

A 的 task_ref 较小但依赖未满足，独立 B 已 ready，允许先给 B 发布 order_key。
A 之后 ready 时只能获得更后的序号。不能预先给未 ready 的 A 占据一个待执行序号，
再让所有核因 A 未就绪而等待。

一旦 A、B 都已被共同准入，参与者遵守其已发布顺序，不能按本核观察 ready 的先后重排。
若存在真实 A→B 数据依赖，B 在 A 的 TASK_DONE 前不会获得 DATA_READY，
因此“允许就绪 B 先执行”不会绕过真实依赖。

现有 producer 的 task_ref 小于 consumer 的校验仍约束 Host DAG；
它不要求独立任务的 order_key 与 task_ref 同序，不能因引入运行时顺序而删除这项图校验。

## 一次性发布共同顺序和成员

### 哪些任务需要共同准入

普通多 block、sync_start、多 lane Mix 使用共同准入；单 block Mix 也包含在内，
因为它仍可能在 kernel 中等待同组 lane。不能让这种单 block 协同任务成为越序旁路。

普通纯 C/V 单 block 沿用现有动态领取，不必逐个加入全局准入序列。
但执行前仍要检查本核已发布的前序参与义务。它只有一个执行位置，且必须满足
“合法输入下自行结束，不隐含等待另一个未声明 task”的 kernel 合同。
无 kernel 的依赖节点沿现有服务路径完成，不凭形状伪装成协同 kernel。

### 参考发布机制

以下是一种可实现的正确性基线，不预设它的性能已经合格：

1. 一个合法领取者从现有 ready 路径唯一取得候选 task 的准入所有权。
2. 准备该 task 的成员、形状、领取策略和必要组关系；输入来自 Host 图和已验证拓扑。
3. 在短的 GM CAS 临界区内确定唯一 order_key，将完整记录接到已发布序列。
4. 完成字段写入与发布顺序后更新连续的可见尾部，再释放临界区。
5. 各参与核独立观察已发布记录，按本核义务推进；不要求全体确认才生效。

临界区只保护记录提交，不能覆盖等待 ready、等待成员空闲、Mix 到达、kernel 调用、
完成轮询或全任务结束。竞争失败者应回到可推进的控制工作，不持锁进入任何 kernel。
它不是专职中央 scheduler，更不是“整个 A 执行期间持有全局锁”。

所有记录由 Host 预分配，运行中只填状态。每个逻辑 task 最多发布一次，
序列容量按可准入 task 数规划，不随 block 领取次数增长。
连续可见尾部之前的记录必须全部完整，不能把先 fetch_add 得到序号当成已发布；
生产者暂停在序号预留与字段写入之间时，消费者不得跳过空洞执行更后任务。

记录至少包含 run_epoch、task_ref、order_key、原始 N、active mask、成员集合 M、
执行／协调／资源角色及分配策略。成员和形状发布后不可变；block cursor 和完成数
是独立可变状态。准入记录不能借用仍由 ready/wake-list 使用的 next_waiter 链接。

### 参与集合的含义

M 是这次准入后可能承担执行、协调或共享资源义务的 worker 集合，
不是“已经开始 kernel 的核集合”。每个 worker 只处理全局序列投影到自己的义务。

纯 AIC 的成员不能为了实现方便扩成全部 AIV。纯 AIV 同理。
Mix 则需要按真实配对、控制和共享资源范围确定成员；
mask 6 没有 AIC kernel，但做组级协调的 AIC 仍有控制义务。

普通动态领取的建议基线是把选定的同类型候选核列为领取成员；
Mix 以候选 cluster 的完整组为成员。成员可以最终没有领到 block，但它在关闭义务之前
仍是潜在领取者，不能把“这次没抢到”当成从未参与。
N 较小时可在准入时缩小成员集合，具体选择／均衡策略须单独测量。

真正不在 M 且无数据依赖的核可以跳过该 task，不等待它完成。
集合一经发布不能加人：某核已经跳过 A 并进入 B 后，不能再把 A 的工作偷取给它。
待准入的 B 可以选取仍在执行 A 的成员，只要共同顺序保证它们先关闭 A，再进入 B。

### 一致性不是全员同时起跑

~~~text
统一发布：order_key(B) = 0，随后 order_key(A) = 1

核 0，参加 B 和 A：B → 本核 B 关闭 → A
核 1，只参加 A：   跳过 B → A
核 2，只参加 B：   B → 后续无关工作
~~~

上例中，核 1 不需要等核 0、核 2 把 B 做完。公共序号解决相交成员的相对次序，
并不把不相交的执行集合串行化，也不要求所有核的局部进度相同。

## 每核准入和既有快速路径

### 局部前沿

每核维护已经观察的连续发布前缀，以及其中最早尚未关闭的本核义务。
扫描到非成员 task 可以跳过；扫描到本核义务不能先跳过再回来执行。
本核关闭 A 的条件由 block 协议定义，不以其他核的进度最小值作门槛。

工作队列空、当前可见序列走完、一次 CAS 失败，都不能推出本轮运行结束；
后续真实前驱完成还会产生新的 DATA_READY 和准入记录。

~~~text
while run 尚未结束:
    处理本核已返回执行的完成，推进既有 wake-list
    处理错误、已承诺的控制发布和本地组收尾
    有界地尝试发布已 ready 的共同准入候选
    取得本核最早未关闭的已发布义务
    if 存在义务:
        只执行该义务的 block 或必要组级服务
        若满足 LocalDone，关闭它并继续
    else:
        从既有路径选择普通单 block 或无 kernel 服务
        执行准入前再次检查共同发布前缀和局部资源
        合法才准备／调用，不能以“早已填入 slot”豁免检查
~~~

普通任务准入与新共同记录发布并发时，必须定义线性化点：
已获准的在途普通 kernel 可以完成，之后不能无限续接后继；
在新义务生效后才尝试准入的普通任务必须等待该义务关闭。
关键读取必须遵守设备可见性合同，不能拿可能过时的本地快照证明“没有前序义务”。

### 三条执行路径都受约束

| 路径 | 可保留的工作 | 不能绕过的条件 |
| ---- | ------------ | -------------- |
| ready pop／steal | 按类型发现并唯一领取 ready 候选 | 共同任务先准入；本核不得越过较早成员义务 |
| completion direct refill | 保留刚解析出的同类型后继，不必重新入队 | 候选 ready 不等于立即允许进入 kernel |
| Mix 发布与执行 | AIC 配对、GM 通知各 lane | 检查 order_key、block 和本核最早组义务 |

两个普通 slot 已预填后序工作时，必须能保留候选身份、释放可重建参数等临时占用，
为较早共同义务让出执行资源；不能以“两个 slot 都满了”永久拒绝必需的 Mix。
也不能把暂存候选伪造为完成或重复入队。若使用重新入队，须另证节点生命周期与 ABA。

当前主循环先执行本核普通 slot，再扫描远端 Mix。新实现必须按共同义务决定准入，
不能照搬这个优先级，使必需的 Mix lane 被不断到来的普通任务挤占。
控制服务可先做，后序 kernel 不可先跑。

## 不变式和进度条件

### 必须成立的不变式

1. 同一 task 仅准入一次，所有参与者观察到相同顺序、成员和形状。
2. 可见序列没有未初始化空洞；已发布成员不可扩张，也不可重排。
3. 每核完成的成员义务构成该核投影的前缀；无义务核不受该前缀约束。
4. 每个 block/subtask 身份唯一执行、唯一计入相应完成层级。
5. 共同驻留任务为不同相互等待 block 保留不同执行位置。
6. LocalDone 不代表 TaskDone；只有后者允许释放真正的数据依赖。
7. 先前准入留下的短暂控制事务必须收尾，不能带着未发布责任进入后序阻塞 kernel。
8. 错误不会变成成功计数，复用存储必须等所有旧访问安全静止。

### 有条件的进度论证

前提包括：有限且有效的 DAG、完成驱动路由不丢工作、准入服务公平推进、记录完整、
成员与资源关系真实、kernel 在其合法参与者到达后能结束。
普通任务不能暗含跨 block 全员 barrier；sync_start 必须满足共同驻留容量。

已准入任务的真实依赖已经完成，不会等待一个尚未获准执行的前驱。
考虑最早尚未关闭的成员义务：相关核只能在它或更早的义务中，不能被更后的
相交协同任务抢走。更早普通任务有限结束，普通分波最终领完，合法共同驻留任务
的参与者最终到达；局部 Mix 资源边也必须遵循相同顺序。
因此不会因 A/B 在不同核上反序进入而产生循环等待。

这个论证允许不同 task 同时在途，不需要 TaskDone 的全局执行屏障。
它不证明 kernel 内部协议、硬件故障或不公平的无限重试能自行恢复。

### 公平性与有界状态

准入候选不能被某个暂停核永久隐藏而没有诊断；有限图也要覆盖长尾和饥饿测试。
短发布临界区不能被持有者带进 kernel。采用 lock-free 替代时，同样要处理
预留空洞、失败生产者和可帮助提交的边界，不能仅因为用了 CAS 就宣称无阻塞。

暂不支持领取后的工作转移。后续若引入，必须同时转移执行和资源义务，
禁止转给已经关闭该 task 的核，Mix 必须整组转移；失败不能回收成双重所有权。

## 生命周期和兼容边界

动态准入序列暂时走完不等于 worker 可以退出。只有全图逻辑终态完整、
准入和领取无在途事务、所有局部组及 trace 收尾完成，才进入既有 AICPU 退出协议。
不得因队列或日志暂空而提前释放设备参数或控制存储。

Host inline 已完成节点不在设备重复计数；仍有前驱的 Dummy 沿完成驱动服务路径
推进一次逻辑终态。不能看见 mask 为零就提前标为成功。

首阶段保留普通单 block 的现有 predicate 合同，未支持的多 block／Mix predicate
继续明确拒绝。后续扩展时，由唯一判定者在 DATA_READY 后发布 RUN／SKIP／ERROR；
SKIP 不伪造 block 执行，也不发布不存在的数据，是否视为逻辑成功沿用既有业务合同。
若在共同准入后才决定跳过，必须另有让所有成员关闭同一义务的协议，不能只取消队列节点。

run_epoch、槽 generation、序号及计数溢出均须显式处理。失败运行停止新的不安全准入，
但还需使已有控制责任收敛；卡在 kernel 内的核不能靠清空 GM 记录取消。
详细内存发布与完成聚合见 [block 与 Mix 执行](block-and-mix-execution.md)。
